ERA VERIFICATION (hard evidence, not a guess)
------------------------------------------------------------------------------
The disc mounts as a real HFS+ volume containing a fully-expanded base system
plus /System/Installation/Packages/*.pkg installer payloads. Read directly
from the mounted volume:

  /System/Library/CoreServices/SystemVersion.plist
    ProductName            = Mac OS X
    ProductVersion          = 10.3
    ProductBuildVersion     = 7B85
    ProductCopyright        = Apple Computer, Inc. 1983-2003

Build 7B85 is documented by MacRumors, AppleInsider and BetaWiki as the
Gold-Master / retail release build of Mac OS X 10.3 Panther, shipped to
Apple Developer Connection on Oct 14 2003 and to retail on Oct 24 2003
(Darwin 7.0.0). This is the actual shipping 10.3 client build -- not a
beta/seed, not a 10.3.x point release, not Jaguar (10.2) and not Tiger (10.4).
This is primary-source evidence (the OS's own installer payload identifying
itself), stronger than a screenshot comparison.

Secondary visual cross-check: reference screenshots were pulled from
GUIdebook Gallery's Mac OS X 10.3 Panther screenshot set
(https://guidebookgallery.org/screenshots/macosx103) --
  - Dock: https://guidebookgallery.org/pics/gui/system/managers/applicationmanager/macosx103-1-1.png
  - Finder sidebar: https://guidebookgallery.org/pics/gui/system/managers/filemanager/macosx103-1-1.png
  - Terminal window: https://guidebookgallery.org/pics/gui/system/utilities/commandprompt/macosx103.png
The Dock screenshot's Finder icon (blue two-tone face, left end of Dock) and
Trash icon (wire-mesh basket, right end of Dock) visually match finder.png /
trash-empty.png pixel-for-pixel in design. The Finder sidebar screenshot's
home-folder house icon matches home.png. The Terminal screenshot confirms
Darwin 7.0.0 (kernel that ships with 10.3) via `uname -a` in the window.

EXTRACTION METHOD
------------------------------------------------------------------------------
1. `hdiutil attach -readonly -nobrowse` to mount the .dmg as a real HFS+
   volume (no files copied/installed, strictly read-only).
2. Most system/Finder icons (trash, folder, home, disk, Apple logo, Internet
   location) are NOT inside a package payload -- they sit already-expanded at
   /System/Library/CoreServices/SystemIcons.bundle/Contents/Resources/*.icns
   directly on the mounted disc. Read straight from there.
3. App-specific icons (Finder.app, Terminal.app, TextEdit.app, Preview.app,
   "Address Book.app") live inside the installer payload
   /System/Installation/Packages/Essentials.pkg/Contents/Archive.pax.gz.
   Extracted with:
     gzip -dc Archive.pax.gz | pax -r './Applications/TextEdit.app' \
       './Applications/Utilities/Terminal.app' './Applications/Preview.app' \
       './System/Library/CoreServices/Finder.app' \
       './Applications/Address Book.app'
   (pax is the classic BSD archiver Apple's installer format uses; selecting
   specific top-level bundle paths avoids extracting the full ~600MB payload.)
4. Each source .icns was rasterized with:
     sips -s format png <file>.icns --out <name>.png
   sips picks the icns family's largest available representation. Before
   trusting the output, every source .icns was parsed by hand (small Python
   script reading the 'icns' chunk table) to confirm it actually contains a
   genuine 128x128 'it32' (24-bit RLE color) + 't8mk' (8-bit alpha mask) pair
   -- i.e. a true native 128px asset, not something sips upscaled. All files
   below except apple-blue.png confirmed it32/t8mk present.
5. Every output PNG was viewed directly (Read tool) to confirm correct
   subject, clean alpha (checked with `magick identify -format
   "%[channels]"`), and no watermarks/artifacts, and dimensions were checked
   with `magick identify`.
